# 阶段四步骤八：部署与全新环境验收

## 自动化离线验收

安装完成后执行：

```powershell
.\scripts\Test-Deployment.ps1
```

脚本只使用 50 封匿名样例，在唯一的 `data/private/deployment-acceptance/<timestamp>/` 目录中完成：

1. 首次工作流分析 50 封并生成 50 个待确认动作；
2. 第二次工作流跳过 50 封未变化邮件；
3. 两次运行的 Graph 写请求均为 0；
4. 检查 Run 统计和动作积压；
5. 执行 Doctor；
6. 创建带完整性和 SHA-256 校验的备份；
7. 对副本执行显式确认的恢复演练，并验证覆盖前备份。

该脚本不会登录邮箱、调用 LLM、显示桌面通知或写回 Outlook。验收产物位于 Git 忽略目录，可在确认无须保留后手动删除。

## 全新目录安装验收

在一个不含 `.venv`、`.env`、私有配置和 `data/private` 的全新代码副本中执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\Install-InboxPilot.ps1
.\scripts\Test-Deployment.ps1
.\scripts\Start-InboxPilot.ps1 -Mode Web
```

检查：

- 安装脚本生成私有模板和目录，数据库 Revision 为最新；
- <http://127.0.0.1:8765/console> 与 `/docs` 可访问；
- 健康检查成功，页面没有泄露正文或密钥；
- 关闭浏览器不结束后台服务；
- 页面“完全退出”会释放端口；
- 重启后 SQLite 中的分析、动作和运行状态仍存在。

## 独立测试邮箱文件夹验收

真实邮箱步骤会读取或修改外部状态，只在独立测试文件夹和明确写回授权下进行：

1. 备份数据库，确认 LLM 默认关闭，启动 Web，并从页面启动自动同步；
2. 向测试文件夹投递一封唯一邮件；
3. 等待一个同步周期，确认后台任务发现、同步并分析该邮件；
4. 在 Web 中查看命中的 YAML 规则、可选 LLM 理由、融合结果、冲突与人工复核原因；
5. 记录邮件原始文件夹、主题、正文、附件状态和用户自有分类；
6. 在页面批准动作，查看零写入预览，并再次确认实际分类差异；
7. 只执行该单一动作，确认只新增 `InboxPilot/` 分类，用户分类被保留；
8. 从页面发起受控回滚，确认只撤销 InboxPilot 分类；
9. 确认邮件位置、主题、正文和附件状态均未变化；
10. 完全退出并重新启动，确认数据库状态、审计记录和去重状态仍存在；
11. 重复同步，确认没有重复写回或重复通知。

## 通过标准

- Windows 安装、启动、后台运行、完全退出、诊断、备份和恢复路径均可复现；
- 全新目录离线验收通过；
- 真实邮箱验收中所有写入都经过批准、预览、精确 Action ID 确认、写前检查、锁和审计；
- 自动工作流始终为 0 Graph 写请求；
- 敏感配置和运行数据始终留在 Git 忽略路径；
- 服务重启后状态持久化，失败任务重跑不产生重复写回。
