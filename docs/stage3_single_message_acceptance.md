# 阶段三后半：个人 Outlook 单封真实写入验收

## 验收结论

2026-08-09，InboxPilot 使用个人 Outlook 邮箱中的专用合成测试邮件完成单封真实分类写入验收，结果通过。

验收仅记录行为结论和请求边界，不提交真实邮箱地址、Message ID、令牌、邮件正文、本地动作队列、审计日志或截图。

## 验收范围

- 使用独立的 `Mail.ReadWrite` 本地配置和加密令牌缓存；
- `write_enabled` 默认关闭，由用户在验收窗口内显式开启；
- 使用只包含一封合成测试邮件的私有数据集、动作队列和审计日志；
- 先完成人工检查、批准和 Graph 写请求数固定为零的 dry-run；
- 使用明确 Action ID、精确幂等键和重复输入 Action ID 的确认门执行；
- 写入目标固定为该邮件的 `categories` 属性；
- 不测试批量写入、真实回滚、移动、删除或发送邮件。

## 验收中发现的升级问题

真实验收发现，阶段三之前生成的 Microsoft Graph Delta Link 会继续沿用旧的 `$select` 查询契约，因此升级后同步的数据可能缺少 `categories` 和 `changeKey`。执行器正确地将空 `changeKey` 视为冲突并拒绝写入，但用户需要手动重置旧同步状态。

本版本为同步状态增加 `query_contract_version: "2.0"`：

- 当前契约要求初始 Delta 查询包含 `categories` 和 `changeKey`；
- 读取到没有当前查询契约版本的旧状态时，自动忽略旧 Delta Link；
- 下一次同步从新的只读初始 Delta 查询开始；
- 现有私有邮件数据集继续保留，并由新查询结果更新；
- 只有完整同步成功后才写入当前版本的 Delta 状态。

这个迁移只影响本地只读同步状态，不会发送 Graph 写请求。

## 尚未覆盖

- 真实回滚 PATCH；
- 网络中断后 `outcome_unknown` 的真实环境对账；

在这些能力完成前，真实执行入口继续保持一次只接受一个明确动作，并且不提供批量模式或自动重试。
